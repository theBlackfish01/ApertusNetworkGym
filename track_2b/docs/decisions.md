## Open questions for the owner

These are implemented as the spec says (or as noted above) and are cheap to change: a change
means re-running `generate.py` (≈ 6 min) and everything downstream of it.

| Question | What the data says | Options |
| --- | --- | --- |
| **Pair intents as intersection** (§3: "intersection of sets; if empty, admissible = reject") | The admissible set is empty for 19 % of I1+I2, 28 % of I1+I3, 15 % of I2+I3 and 4 % of I1+I4 records (`data/stats.json`). On unseen pairs the oracle therefore blocks 11.5 % at load 240 and 14.7 % at 390, against 1.2 % and 6.0 % with no intent, while the MLP blocks 2.8 % and 7.9 % by violating the intent in about 30 % of decisions (`results/tables/results.md`). Lower blocking is not better in that column. Reading "avoid X" as a filter and the other intent as a ranking of what is left leaves about 3–4 % empty (`results/design/spec_measurements.log`, `seq_empty`). | Keep the spec's intersection (implemented), or switch I1 pairs to filter-then-rank. I2+I3 has no such reading (two rankings). |
| **I4 (fewest slots) hardly binds; I2 is close to "take path 0"** | The teacher answers path 0 in 96 % of I4 and 83 % of I2 training records, because candidates are ordered by length and the shortest path usually has the fewest hops and the best modulation. In closed loop, first fit, which ignores the intent, violates I4 in 0.1 % of decisions and the no-intent teacher in 2–4 %; for I2 they violate 10–21 % (`results/tables/results.md`). I4 as defined cannot separate a model that follows it from one that ignores it. | Keep I4 and say so in the report, or replace it with an intent that spreads over paths. I1 and I3 bind well (25–50 % violations when ignored). |
| **I3 definition** | See the deviation above. | Most free slots (implemented) or ONG's utilisation ordering. |
| **Wording** | Ten draft paraphrases per intent in `src/intents.py`. | Edit them there; the first seven of each list are the training ones. |
| **Prompt length** | 1,100 characters on average, 1,550 at most. A stand-in tokenizer counts about 490 tokens on average (see the deviation above), so the 450-token target of §9 is probably missed; the gated Apertus tokenizer decides. Training still fits in 768. | Run `uv run src/train.py --data-dir data/full --dry-run` once `HF_TOKEN` is set. If over: accept it (cost only), or switch the links line to one node sequence per path. |

| 2026-10-09 | uv for every Python environment (`uv sync`, `uv run`); Python 3.12 (`.python-version`). | Owner's instruction; 3.12 matches the Dockerfile in §8 (ONG itself suggests 3.13 but supports ≥ 3.11). |
| 2026-10-09 | All simulation runs in WSL2 Ubuntu 24.04; the repo stays on the Windows drive (`/mnt/c/...`) with `.venv` inside `track_2b/`. | ONG needs Linux (§2). Measured: `uv sync` 82 s; a step takes ≈ 8–10 ms in one process (CPU-bound QoT), so the 9P filesystem is not the bottleneck. |
| 2026-10-09 | No system packages installed: Ubuntu 24.04 already had gcc 13.3, make and the Python 3.12 headers; uv installed user-local (`~/.local/bin`). | `sudo` needs the owner's password; nothing required it. |
| 2026-10-09 | Policy names are ONG dispatch names: `first_fit` (masked first fit) and `jocn_ls_bm_ksp` (`select_jocn_ls_bm_ksp_action`). | ONG labels the first one `KSP-FF-BM` in its legacy sweeps, but it scans path → modulation offset (most efficient first, `_modulation_window_from_max_feasible`) → slot, which is the spec's KSP-BM-FF. |
| 2026-10-09 | `env.reset(options={"only_episode_counters": True})` also resets the step counter, so the protocol window is ended by our own request count, with `episode_length = warmup + window`. | With `episode_length=3000` as written in §7 step 1, the window would run 3,000 requests, not 2,000. `evaluate.py` must do the same. |
| 2026-10-09 | Std across seeds is the sample std (ddof = 1). | Conventional for n = 3 seeds; stated in every table. |
| 2026-10-09 | `.gitattributes` forces LF; `core.fileMode=false`. | The repo is edited from Windows and run from WSL; avoids CRLF in shell/Docker files and spurious mode changes. |
| 2026-10-09 | Every script builds its env with `src/sim.py:build_env`, which returns `ProvisioningEnv`: an `OpticalEnv` that clears ONG's request-analysis cache after each step. | ONG `f7c4491` keeps every `RequestAnalysis` until reset (key includes the allocation-state version, so old entries are never hit again): +0.28 MB per request, ≈ 0.9 GB per 3,000-request episode. The first sweep with 12 workers was killed by the OOM killer. Checked: identical actions and blocking to `make_env` over 800 requests for both heuristics, same speed, flat RSS (test in `tests/test_sim.py`). Worth reporting upstream. |
| 2026-10-09 | `calibrate.py` checkpoints each finished episode to `<out>.partial.jsonl` and resumes from it; default 4 workers (2 used for the day-1 runs). | After the OOM fix, WSL still tore down the Ubuntu distro every 2–5 minutes (`Wsl/Service/E_UNEXPECTED`, `p9io AcceptAsync` cancelled in `dmesg`) with 8, 4 and even 2 workers; the Windows host had 0.5–1.7 GB of 15.7 GB free. `wsl --terminate Ubuntu` did not cure it; `wsl --shutdown` (owner-approved; also restarts Docker Desktop's VM) did, and the run resumed from the checkpoint. If it recurs: close memory-heavy host apps, then `wsl --shutdown`. |
| 2026-10-10 | `results/calibration/day1_sweep.json` was assembled from checkpointed episodes across resumed runs; its `started_utc`/`run_id` belong to the final, resuming invocation. | Episodes are deterministic per (policy, load, seed): all 18 cold-mode episodes match the values printed by the very first run (ONG `make_env`, before the memory fix), and `run_episode` did not change between resumes. |
| 2026-10-10 | Work is tracked by workstream and blockers, not by day (owner's request); README status table follows that. `SPEC.md` §9 is kept as written for reference. | The owner answers asynchronously; what matters is what is blocked on them. |
| 2026-10-10 | Violations are counted on the executed decision (after the first-fit fallback for an invalid answer); invalid answers are counted separately. Rejecting when an admissible path exists is a violation. | One number per request for what actually happened to the network; both raw counts are stored per episode, so other definitions can be recomputed. |
| 2026-10-10 | Results also report violations on "binding" requests: those where the no-intent teacher's own choice is not admissible. | An intent that does not change the right answer cannot be violated by a sensible policy; the binding subset is the sharper test. |
| 2026-10-10 | The intent attached to request *i* of an evaluation episode depends only on the condition, load, seed and the request's candidate paths (a dedicated RNG with a fixed number of draws per request). | Every policy is evaluated on the same intents for the same traffic. |
| 2026-10-10 | Duplicate prompts are dropped before the splits are sampled (first occurrence kept, training episodes first). | A blocked request followed by an identical one yields the same prompt; without this the "no duplicate prompts" check fails inside train. |
| 2026-10-10 | LLM answers are cached per policy name, keyed by the chat messages only (`results/cache/<policy>.jsonl`). | Tables and the `make run` demo can be rebuilt with no GPU, endpoint or environment variable. A different model or decoding setup needs a different policy name. |
| 2026-10-10 | `train.py` is a single PEP 723 script with its own dependencies and writes held-out predictions that `evaluate.py offline --predictions` scores. | It must run as an HF Job (one uploaded file) and the agreement gate must be checkable without the GPU or ONG on that machine. |
