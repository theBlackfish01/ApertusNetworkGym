# Design measurements

One-off measurements that decided how the spec was implemented. They are evidence for
`docs/decisions.md`, not part of the pipeline.

| File | What it is |
| --- | --- |
| `spec_measurements.py`, `.log` | Run on 2026-10-10 against an earlier revision of `src/` (the view then also carried the lowest valid slot over all modulations, and blocks were listed at the path's best modulation only). Seed 11, loads 150/270/390, teacher-driven, requests 300-999. Shows: our path-level BM-LS-KSP matched ONG's in 2,100 of 2,100 decisions; with best-modulation-only blocks the teacher's slot was off the list in 16-18 % of accepts; ONG's load-balancing heuristic picks a most-free-slots path 50-59 % of the time and a first-fit slot 74-79 %; how often each intent's admissible set is empty and how often it changes the decision. The script no longer runs as is; the log is its unedited output. |
| `teacher_variants.py`, `.json` | Closed-loop blocking (protocol window, loads 240 and 390, seeds 1-3) of ONG's BM-LS-KSP against two versions restricted to what the prompt lists: `strict` (blocks valid at the path's most efficient modulation) and `same` (blocks valid at any modulation needing the same number of slots). `same` was adopted: it differs from ONG in 0.05-0.2 % of decisions with the same blocking; `strict` differs in 11-15 % and blocks more. Run it with `PYTHONPATH=src uv run python results/design/teacher_variants.py out.json` (it still runs; `strict` is computed inside the script). |
| `failure_modes.py`, `failure_modes_*.json` | Offline error classes of a model's held-out answers: exact, admissible but not the teacher's choice, reject although an admissible path exists, accept although the set is empty, violation (with the rule broken), not a valid start, malformed; plus rejects on avoid-link requests by the number of admissible paths left. Run on the predictions `train.py` writes: `PYTHONPATH=src python results/design/failure_modes.py results/train/apertus_ft_heldout_predictions.jsonl results/design/failure_modes_apertus_ft_unconstrained.json`. Evidence for the failure-mode paragraph of the report. |
| `closed_loop_failures.py`, `closed_loop_failures_*.json` | The same error classes for the closed loop: finished episodes of a language-model policy are replayed from its answer cache (no GPU; a prompt missing from the cache raises) and every decision is classified. The script checks that the replay reproduces the stored run. `PYTHONPATH=src uv run python results/design/closed_loop_failures.py apertus_ft results/design/closed_loop_failures_apertus_ft.json` (about five minutes on three cores). |
| `pair_rule_leak.py`, `pair_rule_leak_*.json` | Tests whether the reject rule of the training pairs leaks into the single avoid-link intent. Requests that carry only that intent and still have an admissible path are split by whether I1+I2 or I1+I3 would have said reject; the model's reject rate is compared between the two groups, also within each number of admissible paths left. Held-out answers and the closed-loop avoid-link episodes of seed 1 (replayed from the answer cache). `PYTHONPATH=src uv run python results/design/pair_rule_leak.py apertus_ft results/train/apertus_ft_heldout_predictions.jsonl results/design/pair_rule_leak_apertus_ft.json`. |
